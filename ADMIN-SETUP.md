# Администратор и общий контент

## Локальная версия

Страница входа: http://localhost:3000/Health-Plus/login

Email администратора: `makesake632@gmail.com`. Это логин сайта; доступ к почтовому ящику не используется, письма не отправляются.

Начальный случайный пароль сохранён в локальном `admin-credentials.txt`. Файл исключён из Git. Сохраните пароль в своём менеджере паролей; не публикуйте этот файл вместе с сайтом. Для установки нового пароля в PowerShell из корня проекта:

```powershell
.\scripts\set-admin-password.ps1
```

Скрипт запрашивает пароль скрыто, передаёт его через stdin и не записывает в историю команд. После смены пароля старый `admin-credentials.txt` больше не актуален. Все прежние сессии этого администратора аннулируются. Пароль: от 14 до 72 байт UTF-8.

Запуск при работающем Docker Desktop:

```powershell
docker compose up -d --build
npm start
```

База хранится в постоянном Docker-томе `pgdata`. Не используйте `docker compose down -v`, если хотите сохранить данные.

## Перенос старых правок из браузера

Новости, отзывы и вакансии теперь читаются из PostgreSQL. Начальные записи перенесены миграцией. Старые локальные записи не удаляются и не загружаются на сервер автоматически.

1. Откройте сайт в том же браузере и по тому же адресу, где раньше редактировали контент.
2. Войдите новым администратором и откройте главную страницу админки.
3. В блоке «Перенос старых данных» проверьте списки и нажмите перенос для нужных разделов **до их редактирования на сервере**.

Перенос заменяет начальное содержимое одного раздела, сохраняя в том числе пустой список и удаление прежних записей. Операция выполняется одной транзакцией. Если на сервере уже были правки или импорт, API отвечает 409 и ничего не перезаписывает. Копии в браузере сохраняются. Не очищайте их до проверки результата. Если важные правки хранятся в нескольких браузерах, сначала выберите наиболее полный список; остальные записи можно добавить вручную.

После сохранения данные доступны другим посетителям при загрузке страницы; открытая страница также обновляет контент при возвращении в окно. Неопубликованные вакансии и отзывы с оценкой ниже 4 не выдаются публичным API. Редактирование исходных новостей и вакансий отключает их старый встроенный перевод, чтобы он не скрывал новые тексты. Новый текст показывается на обоих языках, пока не будет добавлена отдельная система переводов контента.

## Авторизация

- Пароли хешируются bcrypt (cost 12); открытые пароли в БД не хранятся.
- Случайная сессия на 8 часов передаётся в HttpOnly cookie, SameSite=Strict. В БД хранится только SHA-256 отпечаток токена.
- Все изменения врачей, расписания и контента требуют действующей серверной сессии.
- Запросы изменения проверяют Origin и заголовок `X-Requested-With: clinic-admin`.
- Попытки входа ограничены в PostgreSQL: 10 с одного адреса и 100 суммарно за 15 минут. Учитывается адрес непосредственного соединения, произвольному X-Forwarded-For сервер не доверяет. При размещении за прокси несколько посетителей могут делить один лимит.
- Выход удаляет сессию из БД. Перезапуск API не завершает действующие сессии.
- Без созданного администратора публичные чтения работают, изменения закрыты.

## Перед размещением на хостинге

Сайт и `/api` разместите на одном HTTPS-домене через обратный прокси. Для сервера задайте `COOKIE_SECURE=true`, `ALLOWED_ORIGINS=https://ваш-домен.kz` (точный Origin без пути). Для сборки сайта задайте `REACT_APP_API_URL=/api`. Пересоберите React после изменения этой переменной. Локальный Compose по умолчанию использует `COOKIE_SECURE=false` только для HTTP-разработки.

Используйте отдельный сильный пароль PostgreSQL, закройте публичный доступ к порту 5432 и API-порту 8080, оставив доступ через HTTPS-прокси. Настройте регулярные резервные копии. Текущий путь React `/Health-Plus` при публикации на корне домена потребуется изменить отдельно.

На новом сервере после запуска контейнеров создайте администратора. В Bash пароль вводится скрыто:

```bash
read -r -s -p 'Admin password: ' clinic_password
printf '%s\n' "$clinic_password" | docker compose exec -T api /clinic-admin -email makesake632@gmail.com
unset clinic_password
```

При переносе готовой БД аккаунт переносится вместе с ней; повторная команда нужна только для смены пароля. Секреты не передавайте через аргументы команды или React-переменные.

## Проверки

```powershell
docker compose -p clinic-auth-tests -f docker-compose.test.yml up --abort-on-container-exit --exit-code-from tests
docker compose -p clinic-auth-tests -f docker-compose.test.yml down
$env:CI='true'
npm test -- --watchAll=false --runInBand
npm run build
```

Тестовый Compose использует отдельную временную PostgreSQL без опубликованных портов. Рабочий том не подключается. Проверяются серверные сессии, отказ анонимным изменениям, CSRF, лимиты входа, истечение сессии, CRUD, фильтрация черновиков, перенос и сохранение изменений после повторного запуска миграций. Клиентские проверки покрывают поддельный старый вход, потерю сессии, ошибки сохранения и конфликты импорта.
